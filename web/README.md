# TinyStories 33M in the browser

A 33M-parameter decoder-only language model, trained from scratch on
[TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories), running
entirely on the visitor's device with [onnxruntime-web](https://onnxruntime.ai/docs/tutorials/web/).
The page writes short children's stories from a prompt, streams the tokens, and
shows which backend it is using (WebGPU or CPU) and how fast it is going.

This directory is the web demo. The training code and the checkpoint live in the
parent repository.

## The model

| | |
|---|---|
| Parameters | 33,086,848 |
| Layers | 8 |
| Width | 384 (`d_model`), 6 heads of 64, 2 KV heads (GQA) |
| FFN | 1024, SwiGLU |
| Vocabulary | 50,304 (GPT-2 BPE, padded from 50,257; `<|endoftext|>` is 50,256) |
| Context | 512 tokens |
| Training data | TinyStories, 449,970,176 tokens seen |
| Hardware | GTX 1650 Ti laptop GPU (4 GB), fp32 |
| Time | 20.9 hours |
| Final validation loss | 1.37 on the run's 1M-token eval |

The model uses pre-norm RMSNorm, RoPE, QK-norm, a sigmoid gate on the attention
output, tanh logit soft-capping, and a Muon/AdamW mix. Training details and the
switchable DeepSeek components are in the [parent README](../README.md).

## ONNX export

`../export_onnx.py` wraps the trained modules (no reimplementation) and exports
the inference path with an explicit KV cache:

| Input | Shape | Type |
|---|---|---|
| `input_ids` | `(1, T)` | int64 |
| `position_ids` | `(1, T)` | int64 |
| `past_keys` | `(layers, 1, kv_heads, P, head_dim)` | float32 |
| `past_values` | `(layers, 1, kv_heads, P, head_dim)` | float32 |
| `attention_mask` | `(T, P + T)` | bool |

| Output | Shape |
|---|---|
| `logits` | `(1, T, vocab)` |
| `last_logits` | `(1, 1, vocab)` |
| `present_keys` | `(layers, 1, kv_heads, P + T, head_dim)` |
| `present_values` | `(layers, 1, kv_heads, P + T, head_dim)` |

The prompt is prefilled with `P = 0`; each new token is one call with `T = 1` and
the previous `present_*` tensors as `past_*`. At the 512-token limit the page
re-prefills the last 256 tokens, matching `Transformer.generate` in
`llm/model.py`. The tied embedding is deduplicated after export, which removes a
second 77 MB copy of the weight matrix.

### Precision and quantization

`../measure_parity.py` scores the first 49,664 validation tokens with each
variant and compares every logit with the PyTorch fp32 model:

| Variant | Size | Max abs logit diff | Argmax agreement | Val loss |
|---|---|---|---|---|
| fp32 | 132.7 MB | 4.1e-5 | 100.00% | 1.0501 |
| **fp16 (shipped)** | **66.5 MB** | **0.035724** | **99.91%** | **1.0501** |
| int8 dynamic | 91.7 MB | 2.923301 | 96.46% | 1.0556 |

fp16 passes the ship bar (val loss within 0.01 of fp32, argmax agreement above
98%) and halves the download. int8 is rejected: its argmax agreement is 96.46%,
below the 98% bar, and it is larger than fp16 anyway because only `MatMul`
weights are quantized. fp32 also passes but is twice the size.

The 1.0501 in this table is the loss on the first 49,664 tokens of the validation
file, which is a smaller and easier slice than the run's 1M-token evaluation that
produced 1.3703. Both numbers are correct; they are not comparable.

Cached decoding was checked against a full forward pass over 200 positions
(max abs diff 3.4e-5, 100% argmax), and greedy generation matches PyTorch
`Transformer.generate` token for token.

## Tokenizer

The page tokenizes with `js-tiktoken`'s GPT-2 BPE, the same BPE the model was
trained with (`llm/tokenizer.py`), and prepends `<|endoftext|>` to the prompt as
`sample.py` does. `test/tokenizer.fixtures.json` holds 31 strings (plain text,
punctuation, accents, CJK, Cyrillic, Arabic, emoji, combining marks, zero-width
characters, CRLF, long repetition, ...) generated by Python's `tiktoken`; the web
tests require identical ids and round-trip decoding for all of them. Regenerate
with:

```bash
npm run fixtures:tokenizer
```

## Runtimes and measured speed

The page tries, in order:

1. **WebGPU** through the bundled JSPI build of onnxruntime-web (Chrome/Edge 137+).
2. **WebGPU** through the asyncify build, loaded from `VITE_ORT_EXTERNAL_BASE`
   (default jsDelivr) for browsers with WebGPU but without JSPI. The 28 MiB
   runtime is over Cloudflare's 25 MiB per-file limit, so it is not bundled.
3. **CPU (WASM)** through the bundled threads build. Threads require
   cross-origin isolation; without it, the runtime uses one thread.

A failure falls through to the next option and the reason is shown under
"Details". `?backend=wasm` or `?backend=webgpu` forces one path.

Measurements on an AMD Ryzen 9 8940HX / RTX 5060 Laptop, Chrome 156, generating
100 tokens after the prompt, fp16 (one run; expect a few tokens/s of variance):

| Path | Tokens/s |
|---|---|
| WebGPU (JSPI) | 33.3 |
| CPU, WASM, 8 threads (cross-origin isolated) | 67.3 |
| CPU, WASM, 1 thread (headless Node) | 28.7 |
| onnxruntime-node, CPU | 106.8 |

On this machine the 8-thread CPU path is faster than WebGPU: the model is small
enough that per-token dispatch dominates, and its matrices are small for a
laptop GPU. WebGPU is still tried first because it is the better path on many
other machines; the chip always reports what actually ran.

## Page behavior

- Prompt defaults to `Once upon a time`; Enter with Ctrl/Cmd starts generation.
- Streaming output, Stop button, temperature (0–1.5), top-k (0–100), top-p
  (0.05–1). Temperature 0 is greedy.
- The ~67 MB model file is downloaded once and kept in the Cache API. The cache
  key includes `VITE_MODEL_VERSION`; bump it when publishing a new file.
- Stats: backend, tokens/s, generated tokens, prefill time, runtime, GPU, threads.
- No server-side inference and no analytics; the only network requests are the
  model file, the bundled runtime assets, and (only on non-JSPI browsers) the
  external WebGPU runtime.

## Development

Requirements: Node 20+, and Python with the training repository's dependencies
for exporting or re-measuring the model.

```bash
cd web
npm install

# Export the shipped fp16 graph (also: --variant fp32|int8)
npm run export:model:fp16

# Measure parity, validation loss and cache equivalence
../.venv/bin/python ../measure_parity.py --variants fp32 fp16 int8

# Generate the torch greedy fixture used by the end-to-end test
../.venv/bin/python ../make_generation_fixture.py

# Tokenizer fixtures from Python tiktoken
npm run fixtures:tokenizer

npm run dev            # http://localhost:5173, model from web/model/
npm test               # tokenizer, sampling, static config, ONNX end-to-end
npm run typecheck
npm run bench          # headless generation parity + tokens/s
```

`npm run dev`, `npm run build:local` and `npm run preview` serve `model/*.onnx`
from `web/model/` at `/model/...`; the files are not under `public/`, so they are
never copied into `dist/`.

### End-to-end and browser checks

`npm test` loads `model/model_fp16.onnx`, generates with the same tokenizer,
sampler and cache as the page, and requires the exact token ids from
`test/fixtures/generation.json` (produced by PyTorch greedy decoding), both
through onnxruntime-node and through the WASM build of onnxruntime-web.

For the real page, headless Chrome is driven by `scripts/browser-check.mjs`:

```bash
npm run build:local
npm run test:browser           # both backends; or: node scripts/browser-check.mjs wasm
```

It starts `vite preview`, waits for the model, generates 100 tokens, checks that
the requested backend actually started, writes `test/out/browser.json`, and saves
screenshots. Results from the last local run are in `test/out/`.

## Build and deploy

Production builds expect the model on Hugging Face, because it is over
Cloudflare's 25 MiB per-file limit:

```bash
npm run build                  # VITE_MODEL_URL from .env.production
npm run build:local            # same bundle, model from /model/ (local preview)
```

Before deploying:

1. Upload `model/model_fp16.onnx` to the Hugging Face repo
   (`xxparthparekhxx/tinystories-33m`).
2. Pin `.env.production` to the commit hash instead of `main`, and set a new
   `VITE_MODEL_VERSION` if the file changed.
3. `npm run build`, then `npx wrangler deploy` from `web/`.

`public/_headers` sets COOP/COEP for cross-origin isolation (WASM threads),
long-lived caching for `/assets/*` and `/ort/*`, and revalidation for the page.
`wrangler.jsonc` is assets-only and maps the site to
`llm.parthparekhdev.com`. The build fails if anything in `dist/` exceeds 25 MiB
or if a `model/` directory sneaks in.

Nothing in this directory has been deployed or pushed; the model URL in
`.env.production` is a placeholder until the file is uploaded.
